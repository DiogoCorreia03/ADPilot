# Penetration Testing Report

**Date:** September 7, 2026
**Assessment Scope:** Network infrastructure involving a Domain Controller (192.168.122.10) and a Member Host (192.168.122.5) within the `polaris.local` domain.
**Objective:** Identify security weaknesses, enumerate domain structure, and demonstrate feasible attack paths using offensive security techniques.

***

# Executive Summary

This report details the findings of a comprehensive penetration test conducted against the `polaris.local` infrastructure. The assessment successfully demonstrated key security weaknesses in Active Directory (AD) configuration and network service exposure.

**Overall Compromise Achieved:** Limited Data Access and Remote Command Execution. The assessment achieved read-only access to sensitive domain information (user lists, group memberships, computer objects) and established remote command execution capabilities on the member host (192.168.122.5).

**Highest Level of Compromise:** Successful lateral movement and data enumeration on the member host using captured credentials, but **Domain Administrator compromise was not achieved.**

**Key Metrics:**
*   **Hosts Discovered:** 2 (192.168.122.10, 192.168.122.5)
*   **Accounts Discovered:** Multiple users identified (e.g., saul.goodman, skyler.white, hank.schrader).
*   **Accounts Compromised:** 2 (skyler.white, hank.schrader)
*   **Credentials Obtained:** 2 (Plaintext passwords for skyler.white and hank.schrader).
*   **Critical Vulnerabilities:** Anonymous LDAP Binding, Weak Password Enforcement, and Unauthenticated Remote Management Exposure (WinRM).

**Critical Observations:**
1.  **Anonymous LDAP Access:** The Domain Controller permits anonymous LDAP binds, allowing basic domain enumeration without authentication.
2.  **Weak Credential Management:** Two service accounts (`skyler.white` and `hank.schrader`) were compromised via password spraying, demonstrating a failure in password complexity or policy enforcement.
3.  **Remote Management Exposure:** The member host exposes WinRM (HTTP/5985) with effective remote command execution capabilities, enabling attackers to execute commands using valid domain credentials.

***

# Attack Path Summary

The attack path followed a clear progression from passive reconnaissance to authenticated lateral movement, culminating in deep system enumeration.

### Path 1: Initial Reconnaissance and Discovery (Non-Attacker)
*   **Discovery:** Anonymous LDAP enumeration was successful, confirming the domain name (`polaris.local`) and identifying the domain controller's SRV record (`_ldap._tcp.dc._msdcs.polaris.local`).
*   **Weakness:** Anonymous LDAP binding was permitted on Port 389, allowing initial mapping of the directory service structure.
*   **Systems Affected:** Domain Controller (192.168.122.10).

### Path 2: Credential Acquisition (Attack Focus)
*   **Initial Access/Vector:** Password Spraying attack leveraging common wordlists against known user accounts.
*   **Intermediate Steps:**
    *   The attacker successfully used the `kerbrute` tool to attempt spray attacks against multiple users.
    *   **Success:** The attack yielded two valid credentials: `skyler.white@polaris.local:Password123` and `hank.schrader@polaris.local:sHyangja210`.
*   **Credentials Obtained:** Two valid, usable domain credentials.
*   **Systems Affected:** Domain Controller (192.168.122.10).

### Path 3: Active Directory Enumeration (Authenticated Lateral Movement)
*   **Initial Access:** Utilizing the newly acquired valid credentials (`skyler.white:Password123`).
*   **Intermediate Steps:**
    *   The attacker authenticated to the Domain Controller's LDAP service (192.168.122.10).
    *   Comprehensive dumps of user accounts, computer objects, and security group memberships were executed.
    *   **Discovery:** Full lists of organizational units, members, and attributes were successfully retrieved, detailing organizational structure and potential high-value targets (e.g., potential Domain Admin groups).
*   **Privilege Escalation:** None demonstrated. The scope was read-only enumeration.
*   **Systems Affected:** Domain Controller (192.168.122.10).

### Path 4: Lateral Movement to Member Host (Authenticated Remote Execution)
*   **Initial Access:** Using the valid credentials (`skyler.white:Password123`) to establish a remote session on the member host.
*   **Intermediate Steps:**
    *   The attacker identified the exposed WinRM service (HTTP/5985) on 192.168.122.5.
    *   Using the credentials, the attacker successfully executed remote commands (`whoami /all`) via WinRM protocol.
    *   **Discovery:** Remote command execution was successfully established, proving the ability to execute arbitrary code on the member host.
    *   **Attempted Escalation:** Attempts were made to dump local credentials and dump system hashes, but these were blocked due to insufficient or incorrect local privilege/permissions, limiting the compromise to command execution only.
*   **Credentials Obtained:** Valid remote access established using `skyler.white:Password123`.
*   **Systems Affected:** Member Host (192.168.122.5).

# Findings

### 1. Anonymous LDAP Bind Permitted
**Title:** Anonymous LDAP Bind Permitted on Domain Controller
**Evidence:** LDAP Service Banner confirms service availability on Port 389. Task 1.1.1 reports successful anonymous bind.
**Affected Systems:** Domain Controller (192.168.122.10)
**Description:** The Domain Controller allows external clients to establish an LDAP connection and perform basic service queries (e.g., SRV record discovery) without requiring any authentication credentials.
**Impact:** High. This facilitates initial reconnaissance for attackers, allowing them to map the domain structure, identify domain controllers, and discover potential service targets without any authorization.
**Attack Path in which it appeared:** Initial Reconnaissance (Path 1).

### 2. Weak Password Policies / Successful Password Spraying
**Title:** Compromise via Password Spraying Attack
**Evidence:** Task 1.3.3 successfully compromised the account `skyler.white@polaris.local` using the password `Password123`. Task 1.3.5 successfully compromised the account `hank.schrader@polaris.local` using the password `sHyangja210`.
**Affected Systems:** Domain Controller (192.168.122.10)
**Description:** The service accounts utilized by multiple employees (`skyler.white`, `hank.schrader`) were susceptible to compromise using common, weak passwords combined with a spray attack, indicating insufficient password complexity, poor change management, or failure to enforce strong policies.
**Impact:** Critical. Compromise of single user accounts provides initial footholds for lateral movement and internal data exfiltration.
**Attack Path in which it appeared:** Credential Acquisition (Path 2).

### 3. Exposed Remote Management Service (WinRM)
**Title:** Unrestricted WinRM Connectivity on Member Host
**Evidence:** Task 4.3.3 and Task 4.2.2 confirmed successful connection and command execution via WinRM (Port 5985) using credentials `skyler.white:Password123`.
**Affected Systems:** Member Host (192.168.122.5)
**Description:** The member host exposes the WinRM service over HTTP without requiring advanced authentication mechanisms or rate limiting. This allowed an attacker who possesses valid credentials to execute arbitrary commands remotely, bypassing the need for physical access or traditional SMB lateral movement exploits.
**Impact:** High. This allows for immediate, remote code execution and operational compromise of the system using only valid, low-privilege credentials.
**Attack Path in which it appeared:** Lateral Movement (Path 4).

# Lateral Movement

Lateral movement was successful via two distinct vectors:

1.  **Directory Service Movement (192.168.122.10):** The compromise of `skyler.white`'s credentials enabled the attacker to move *logically* within the AD structure, gathering comprehensive intelligence about the entire domain's user and group topology.
2.  **Remote Execution Movement (192.168.122.5):** The attacker used the WinRM service on the member host (192.168.122.5) to achieve direct remote command execution using the compromised service account credentials.

***

# Privilege Escalation

**None successful.**

While the assessment demonstrated multiple attempts at privilege escalation (including attempts to dump NTDS.DIT and forge tickets), all attempts failed due to technical blockers, authentication errors, or inadequate privileges. The successful compromise was restricted to read-only enumeration and execution as a standard domain user.

***

# Domain Compromise

**Domain compromise was not achieved.**

Attempts to execute advanced domain takeover techniques failed:
*   **DCSync/NTDS.DIT Dump:** Failed with replication errors and principal unknown errors (KDC\_ERR\_S\_PRINCIPAL\_UNKNOWN), indicating strict controls or insufficient privileges for the service account.
*   **Kerberos/Golden Ticket:** Attempts failed due to Kerberos protocol errors, suggesting that the prerequisite highly privileged hashes (e.g., KRBTGT hash) could not be acquired.

***

# Failed Attack Paths

These paths were investigated and provide critical security insights:

1.  **Kerberoasting (Service Principal Name Attacks):** Attempts to perform Kerberoasting against service accounts like `cifs/fileserver.polaris.local` failed with `KDC_ERR_C_PRINCIPAL_UNKNOWN`. This indicates that either the service principal names are incorrectly configured, or the service accounts are not actively registered in a manner that allows the attack.
2.  **NTDS.DIT Hash Dumping:** Attempts to dump the Domain Controller database using `skyler.white`'s credentials failed due to session and replication errors, demonstrating that the DC is protected against simple hash extraction attempts.
3.  **Deep Share Enumeration:** Attempts to list specific departmental shares or administrative shares (C$, ADMIN$) on 192.168.122.5 failed, even with the compromised credentials, suggesting that share access may be restricted beyond the initial login level.

# Recommendations

The following recommendations are directly linked to the vulnerabilities demonstrated during this assessment.

### Addressing Anonymous Directory Services Access
**Remediation:** Immediately implement and enforce strong LDAP authentication requirements for all directory queries.
**Action Items:**
1.  Implement network access control lists (ACLs) on the Domain Controller to block anonymous binds on LDAP/LDAPS ports.
2.  Require client authentication for all directory service interaction.

### Addressing Weak Password Policies / Compromise via Password Spraying
**Remediation:** Enforce robust and non-reusable password policies and implement account hardening.
**Action Items:**
1.  Mandate complex, unique passwords for all user and service accounts.
2.  Implement Multi-Factor Authentication (MFA) for all domain access and critical services.
3.  Review and immediately rotate the passwords for all identified service accounts (`skyler.white`, `hank.schrader`).

### Addressing Exposed Remote Management Service (WinRM)
**Remediation:** Restrict and secure access to remote management protocols.
**Action Items:**
1.  Enforce strict firewall rules, limiting WinRM (5985) access only to necessary management workstations and source IPs.
2.  Utilize strong authentication methods (e.g., Certificate-based authentication or Kerberos Constrained Delegation) rather than simple user/password authentication for WinRM access.
3.  Monitor the logs for unexpected use of WinRM, especially command execution attempts.
