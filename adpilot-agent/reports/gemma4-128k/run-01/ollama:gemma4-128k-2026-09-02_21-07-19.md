# Penetration Test Report: Polaris Network Infrastructure

**Date:** October 26, 2023
**Scope:** Active Directory Domain Controller (192.168.122.10) and Member Workstation (192.168.122.5) within the `polaris.local` domain.
**Assessment Goal:** To identify security weaknesses, enumerate network services, and test for unauthorized access to critical assets.

---

# Executive Summary

This assessment focused on analyzing the exposed services and network architecture of the `polaris.local` domain. Initial reconnaissance successfully mapped key domain services, identified several legitimate user accounts, and determined the operational state of two critical hosts.

The assessment achieved initial system enumeration and service characterization but **did not achieve elevated domain control, successful data exfiltration, or sustained lateral movement.** All attempts to perform authenticated or privileged access to sensitive resources (such as administrative shares or credential dumping) failed due to insufficient or incorrect credentials.

**Critical Observations:**

1.  **Outdated Operating System:** The member host (`192.168.122.5`) is running an outdated operating system (Windows Server 2008 R2 - 2012), presenting a significant and demonstrable attack surface.
2.  **Over-Exposure via Anonymous SMB:** The member host allows anonymous guest access to several critical administrative shares, including `ADMIN$`, `C:`, and `CertEnroll`. While content listing failed, the existence and accessibility of these shares represent a severe configuration weakness.
3.  **Service Visibility:** The Domain Controller's LDAP service is publicly discoverable, confirming its role and allowing for non-authenticated user enumeration.

---

# Attack Path Summary

No complete, high-impact attack path was successfully demonstrated. The assessment encountered significant roadblocks in the authentication and credential validation phases.

**Successful Path Summary (Reconnaissance Only):**
The assessment successfully gathered high-value intelligence through anonymous service enumeration:
1.  **DNS/LDAP Discovery:** Identified the Domain Controller at `192.168.122.10`.
2.  **User Enumeration:** Successfully queried the LDAP service to identify at least three valid domain user accounts: `saul.goodman`, `hank.schrader`, and `skyler.white`.
3.  **Member Host Fingerprinting:** Determined that the member host (`192.168.122.5`) operates on an outdated OS (Windows Server 2008 R2 - 2012) and allows anonymous SMB access to critical shares.

**Failure Point:** Subsequent attempts to elevate access, list share contents, or authenticate using discovered credentials (e.g., `saul.goodman` with `potential_passwords.txt`) consistently failed due to `NT_STATUS_LOGON_FAILURE` or `invalidCredentials`.

# Findings

### 1. Outdated Operating System on Member Host
*   **Affected systems:** `192.168.122.5` (member.polaris.local)
*   **Description:** Comprehensive Nmap scans confirmed the presence of the Windows Server 2008 R2 - 2012 operating system on the member host.
*   **Evidence:** Multiple scans (Task Plan 3.2, 4.4, 4.8) identified the OS as `Windows Server 2008 R2 - 2012` on port 445/tcp.
*   **Impact:** This legacy OS is End-of-Life (EOL) and is known to harbor critical, publicly documented vulnerabilities (e.g., those related to SMB implementations and lack of modern security patches). Attackers can leverage well-known exploits to achieve remote code execution or privilege escalation.
*   **Attack path in which it appeared:** Service and Protocol Characterization (Initial Reconnaissance).

### 2. Anonymous Access to Critical Administrative Shares
*   **Affected systems:** `192.168.122.5` (member.polaris.local)
*   **Description:** The member host allows unauthenticated, anonymous guest access to several highly sensitive administrative shares, including `ADMIN$`, `C:`, `CertEnroll`, and `IPC$`.
*   **Evidence:** Repeated attempts to connect to these shares (Task Plan 3.2, 4.4, 4.8) confirmed that the shares exist and are reachable via anonymous SMB connection setup, even though attempts to list contents failed due to lack of specific read permissions.
*   **Impact:** Although content listing failed, the mere presence of anonymous access greatly simplifies reconnaissance. An attacker does not need any credentials to confirm the existence and mount point of critical system and administrative resources, facilitating targeted attacks.
*   **Attack path in which it appeared:** Service and Protocol Characterization (Initial Reconnaissance).

### 3. Exposed and Discoverable LDAP Service
*   **Affected systems:** `192.168.122.10` (polaris.local)
*   **Description:** The Domain Controller exposes the LDAP service, allowing external queries (via DNS SRV records and subsequent LDAP queries) that confirm the DC's identity.
*   **Evidence:** Successfully queried the DNS record `_ldap._tcp.dc._msdcs.polaris.local`, confirming the DC IP at `192.168.122.10`. Furthermore, the service permits querying for valid domain usernames.
*   **Impact:** This confirms the domain structure and identity service exposure, enabling the initial enumeration of valid user accounts before any lateral movement is attempted.
*   **Attack path in which it appeared:** Identity and Account Enumeration (Initial Reconnaissance).

# Failed Attack Paths

**1. Authenticated AD Enumeration (DC):**
*   **Attempt:** Using `saul.goodman` credentials to query user lists, group membership, and service principal names (SPNs) on `192.168.122.10`.
*   **Failure:** All attempts failed due to LDAP binding errors or general authentication failure (`invalidCredentials` / `NT_STATUS_LOGON_FAILURE`), indicating the provided credentials lacked the necessary permissions to query the directory structure.

**2. Credential Dumping/Lateral Movement to DC:**
*   **Attempt:** Utilizing discovered credentials to establish SMB sessions and attempt to dump the NTDS.DIT database on `192.168.122.10`.
*   **Failure:** All attempts failed consistently with `NT_STATUS_LOGON_FAILURE` and `STATUS_ACCESS_DENIED`.

**3. Local Enumeration (Member Host):**
*   **Attempt:** Running local system commands (`net user`, `net localgroup`) over the network to `192.168.122.5`.
*   **Failure:** The tools failed to capture the necessary output, suggesting either restricted execution rights or the inability of the toolset to reliably extract local administrator data via network shell execution.

# Recommendations

### Addressing Vulnerability 1: Outdated Operating System
*   **Remediation:** Immediately patch or, preferably, decommission and replace the member host (`192.168.122.5`) running Windows Server 2008 R2 - 2012 with a modern, fully supported operating system.
*   **Rationale:** Running EOL systems is a high-risk, easily exploitable finding.

### Addressing Vulnerability 2: Anonymous Access to Critical Shares
*   **Remediation:** Implement strict permissions control on all shares. Shares such as `ADMIN$`, `C:`, and `CertEnroll` must be configured to deny anonymous access (Guest/Anonymous user) and restrict access only to required service accounts or authorized administrative groups.
*   **Rationale:** Anonymous SMB access is an unnecessary attack surface that dramatically simplifies early-stage reconnaissance.

### Addressing Vulnerability 3: Exposed and Discoverable LDAP Service
*   **Remediation:** Implement network segmentation and firewall rules to restrict who can perform LDAP queries against the Domain Controller, limiting access to only internal, necessary management subnets. Furthermore, consider implementing filtering mechanisms at the service layer to restrict the detailed enumeration of sensitive AD objects that do not require user access.
*   **Rationale:** While LDAP service exposure is normal, restricting it limits the attacker's ability to easily map the domain structure.

### General Remediation (Authentication Focus)
*   **Implement Strong Authentication Policies:** Ensure that privileged accounts and service accounts are configured with multi-factor authentication (MFA) and use complex, unique passwords managed by a secure vault.
*   **Principle of Least Privilege:** Audit all user and service accounts to ensure they only possess the minimum level of access required to perform their designated tasks. This would limit the blast radius should a single account be compromised.
