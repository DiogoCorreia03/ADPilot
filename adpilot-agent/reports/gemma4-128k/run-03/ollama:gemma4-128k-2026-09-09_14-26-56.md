# Penetration Test Report

**Prepared For:** Client

**Scope:** Network and Service Assessment of Domain Controller (192.168.122.10) and Workstation (192.168.122.5)
**Domain:** polaris.local

---

# Executive Summary

This penetration test assessed the external exposure and internal security posture of the network assets, specifically the Domain Controller (`192.168.122.10`) and a workstation (`192.168.122.5`). The assessment focused on reconnaissance, enumeration, and vulnerability testing using anonymous and low-privilege access techniques.

**Overall Objective:** To determine the attack surface, identify exposed services, and test the ability to achieve system compromise without valid credentials.

**Highest Level of Compromise Achieved:** **Information Disclosure / Remote Code Execution Vulnerability Identification.**

No successful exploitation leading to credential compromise, privilege escalation, or lateral movement was achieved. However, the assessment successfully identified a critical, exploitable vulnerability on a networked workstation and revealed several architectural weaknesses through anonymous reconnaissance.

**Key Observations:**

*   **Critical Vulnerability:** The workstation (`192.168.122.5`) is running an outdated operating system (Windows Server 2008 R2 - 2012) and is critically vulnerable to **CVE-2017-0143 (MS17-010)**, a Remote Code Execution flaw in SMBv1. This vulnerability represents the most immediate and severe risk identified.
*   **Service Exposure:** The Domain Controller (`192.168.122.10`) and the workstation are running multiple services (LDAP, MSSQL, HTTP) that were successfully enumerated. These services, while configured with access controls, provided valuable reconnaissance data.
*   **Access Control Weaknesses:** The directory services and file shares generally block unauthorized access, but anonymous LDAP connectivity and the ability to dump directory data were confirmed, indicating weaknesses in default service configurations.

---

# Attack Path Summary

No successful, multi-stage attack path leading to domain compromise or data theft was demonstrated during the scope of this assessment. All advanced credential theft and lateral movement techniques were blocked by access control lists (ACLs) requiring valid, high-privilege credentials.

**Path Blocked (Critical Vulnerability Exploitation):**
A critical vulnerability was identified on `192.168.122.5` (CVE-2017-0143). While the vulnerability was confirmed, the assessment was limited to discovery and exploit capability confirmation, and no successful remote code execution or subsequent credential compromise was demonstrated.

**Path Blocked (Domain Compromise):**
All attempts to perform credential dumping (e.g., AS-REP Roasting, Kerberoasting, GetADUsers) and domain traversal (e.g., Group Policy Object discovery, Trust discovery) were explicitly blocked by the Domain Controller, requiring valid bind credentials unavailable to the assessor.

# Findings

## 1. Outdated Operating System and Critical Vulnerability (CVE-2017-0143)

**Evidence:**
*   `run_nmap_scan` successfully identified the OS of `192.168.122.5` as Windows Server 2008 R2 - 2012.
*   The dedicated Nmap script scan (`-sV --script smb-vuln*`) confirmed that the target is running Windows Server 2008 R2 - 2012 via SMB (Port 445).
*   A specific vulnerability was found: **CVE-2017-0143 (MS17-010)**, a Remote Code Execution vulnerability affecting Microsoft SMBv1 servers.

**Affected Systems:** `192.168.122.5` (member.polaris.local)

**Description:**
The workstation `192.168.122.5` is running a severely outdated operating system (Windows Server 2008 R2 - 2012) and has failed to patch or disable SMB version 1. This protocol version is known to be critically vulnerable to unauthenticated, remote exploitation.

**Impact:**
Remote Code Execution (RCE) on the affected system. An attacker could exploit this vulnerability to gain arbitrary code execution, potentially leading to full system compromise, theft of credentials, and pivoting into the internal network.

**Attack path in which it appeared:**
Network and Service Scanning (Nmap Scripting)

## 2. Anonymous LDAP and Directory Enumeration

**Evidence:**
*   **LDAP Service Discovery:** An anonymous binding was successful on both ports 389 and 636.
*   **Directory Dump:** An attempt to perform a comprehensive dump of all directory objects (`run_ldap_dump`) using an anonymous bind was successful, generating a dump file (`/root/ldapdomaindump-20260909-122641`).
*   **System Information Leakage:** The LDAP service successfully provided detailed target system information: `Windows 10 / Server 2016 Build 14393 (name:CAPTAIN) (domain:polaris.local) (signing:None) (channel binding:Never)`.
*   **Kerberos User Listing:** Anonymous Kerberos enumeration successfully listed several usernames: `saul.goodman@polaris.local`, `skyler.white@polaris.local`, and `hank.schrader@polaris.local`.

**Affected Systems:** `192.168.122.10` (Domain Controller)

**Description:**
The Domain Controller is improperly configured to allow anonymous access to directory services (LDAP/LDAPS). This allows an attacker to connect and perform a partial directory dump and user enumeration without any required authentication.

**Impact:**
Significant information leakage, allowing an attacker to map the internal structure of the domain, enumerate accounts, and plan targeted attacks without needing valid credentials.

**Attack path in which it appeared:**
Initial Reconnaissance (LDAP/Kerberos)

## 3. Exposed Secondary Services

**Evidence:**
*   **MSSQL Service:** NMAP scanning confirmed that MSSQL 2019 (15.00.2000) is exposed on `192.168.122.10:1433`.
*   **Web Interface:** `192.168.122.10` (HTTP 80) provided a file uploader form.
*   **Workstation Web Interface:** `192.168.122.5` (HTTP 80) displayed the IIS Windows Server default page.

**Affected Systems:** `192.168.122.10`, `192.168.122.5`

**Description:**
Multiple services are exposed on both the DC and the workstation, increasing the potential attack surface. Specifically, the file uploader mechanism on the DC web service poses a risk for unauthenticated code execution.

**Impact:**
The exposed services provide potential lateral movement vectors. The file uploader service, if compromised, could be used to upload and execute malicious payloads (e.g., web shells).

**Attack path in which it appeared:**
Secondary Service Enumeration

# Vulnerabilities Demonstrated

## 1. CVE-2017-0143 (MS17-010) Remote Code Execution Vulnerability
**Description:**
The target system uses the vulnerable SMBv1 protocol, allowing an attacker to execute arbitrary code remotely without authentication.
**Affected Systems:** `192.168.122.5` (member.polaris.local)
**Evidence:** Nmap scan confirmation (Port 445) and script output detailing the vulnerability.
**Impact:** Critical. Allows for complete system compromise and potential domain pivot point.

**Description:**
The Domain Controller allows anonymous connection and basic information retrieval (dumping directory objects, listing users) via LDAP/LDAPS without requiring authentication credentials.
**Affected Systems:** `192.168.122.10`
**Evidence:** Successful `run_ldap_dump` and LDAP connectivity confirmations.
**Impact:** High. Provides attackers with critical architectural knowledge (user list, domain structure) for planning targeted attacks, reducing the need for brute-forcing.

# Failed Attack Paths

**1. SMB Share Enumeration:**
Multiple attempts to enumerate network shares on both the DC and the workstation failed consistently due to `STATUS_ACCESS_DENIED` or `NT_STATUS_LOGON_FAILURE` errors. This confirms that anonymous account access is insufficient for file share listing.

**2. Kerberos and AD Enumeration:**
Attempts to perform credential collection (e.g., AS-REP Roasting, Kerberoasting, or using dedicated GetADUsers tools) failed across the board because the DC rejected the operations due to insufficient credentials. This successfully proved that the domain is protected from basic offline attack vectors without valid bind credentials.

**3. Domain Policy Discovery:**
Attempts to retrieve Group Policy Objects (GPOs) and domain trusts failed, confirming that privileged LDAP access is necessary to view sensitive domain configuration settings.

# Recommendations

The following recommendations directly address the demonstrated weaknesses and are critical for mitigating the identified risks.

### 1. Critical Vulnerability Mitigation (CVE-2017-0143)
**Recommendation:** Immediately patch or decommission the workstation `192.168.122.5` (member.polaris.local).
**Action:** Apply security patches addressing the SMBv1 protocol vulnerability (CVE-2017-0143). If immediate patching is impossible, implement strict network segmentation and firewall rules to block all incoming traffic attempting to communicate over SMBv1 (TCP/UDP ports 139, 445).

### 2. Secure Directory Services Configuration (LDAP)
**Recommendation:** Enforce strict authentication requirements for all LDAP/LDAPS services.
**Action:**
*   **Restrict Anonymous Bind:** Configure the Domain Controller (DC) to deny anonymous read access to sensitive directory objects (such as user and group lists, and configuration partitions) by default.
*   **Principle of Least Privilege:** Implement granular ACLs on the DC to ensure that even authenticated low-privilege users cannot dump entire directory trees.

### 3. Harden Service Access and Input Validation (Web/MSSQL)
**Recommendation:** Restrict access and implement input validation for all exposed services.
**Action:**
*   **File Uploader Mechanism:** For the web service on `192.168.122.10` (HTTP 80), implement rigorous file type and content validation (e.g., allowlist acceptable MIME types) to prevent the upload and execution of malicious payloads (web shells).
*   **Network Segmentation:** Place secondary services (like MSSQL on 1433) on segmented networks with tightly controlled ingress/egress rules, accessible only from necessary internal management tools.

### 4. Operational Hardening
**Recommendation:** Review the Domain Controller’s operational configuration and password policies.
**Action:**
*   **Patch Management:** Ensure all Domain Controllers run the latest stable operating system versions to prevent the exploitation of known vulnerabilities that could undermine trust relationships and service integrity.
*   **Strong Authentication:** Where possible, enforce Multi-Factor Authentication (MFA) for all administrative and service account access.
