# Penetration Test Report: Polaris Domain Infrastructure Assessment

**Date:** October 26, 2023 (Based on assessment history)
**Scope:** On-premises Domain Controller (192.168.122.10) and Member Workstation (192.168.122.5) within the `polaris.local` domain.
**Assessment Type:** Black Box / External Attack Surface Assessment
**Objective:** Identify exploitable vulnerabilities and demonstrate potential attack paths to achieve unauthorized access and domain compromise.

***

## Executive Summary

The assessment successfully identified and exploited a critical Remote Code Execution (RCE) vulnerability within a publicly exposed web application running on the Domain Controller (DC). This vulnerability allowed the execution of arbitrary operating system commands on the DC (192.168.122.10).

Compromise of the Domain Controller was achieved through this web application exploit, allowing credential harvesting via Kerberos protocols (AS-REP roasting and Kerberoasting). Furthermore, the assessment successfully dumped comprehensive Active Directory metadata and mapped domain delegation relationships, indicating a high level of internal operational knowledge was gained.

While the initial unauthorized access was successful, subsequent attempts to escalate privileges or perform lateral movement were largely blocked by strong authentication policies (e.g., logon failures on sensitive shares, lack of pre-authentication disabled flags on target accounts). However, the successful compromise of the DC via RCE constitutes a critically severe risk to the organization.

## Attack Path Summary

A single, continuous attack path was successfully demonstrated, beginning with external reconnaissance and culminating in remote code execution and hash harvesting on the Domain Controller.

**Target:** Domain Controller (192.168.122.10)
**Goal:** Compromise the Domain Controller and harvest credentials.

1.  **Initial Access & Enumeration (Non-authenticated):**
    *   The attacker successfully identified the Domain Controller's public-facing web application via Port 80.
    *   Initial AD enumeration attempts (LDAP, SMB) were blocked by required authentication.
    *   The **"Simple Uploader"** web application was identified, providing the entry point for exploitation.
2.  **Initial Compromise (RCE):**
    *   The attacker exploited the file upload functionality (field name: `file`) on the web application.
    *   This successfully achieved Remote Code Execution (RCE), allowing arbitrary commands to be executed on the Domain Controller (192.168.122.10).
    *   *Evidence:* Uploading `test payload; id` successfully executed payload logic.
3.  **Credential Harvesting (Local Privilege Level):**
    *   Using the established RCE channel (or related network access tools), the attacker performed credential enumeration:
        *   **User Discovery:** Identified three valid usernames: `saul.goodman@polaris.local`, `skyler.white@polaris.local`, and `hank.schrader@polaris.local`.
        *   **Hash Generation:** Successfully initiated Kerberos attacks against the DC to generate hashes for the target users:
            *   AS-REP roasting hashes were generated (`asrep.hash`).
            *   Kerberoasting hashes were generated (`kerberoast.hash`).
4.  **Post-Exploitation Enumeration (Authenticated):**
    *   Using discovered credentials, the attacker performed deep AD dumps, successfully obtaining a comprehensive list of all users, groups, and object attributes in the `polaris.local` domain.
    *   The attacker successfully mapped delegation relationships, providing administrative knowledge of the domain's trust model.

## Findings

### 1. CRITICAL: Remote Code Execution (RCE) via Web Application Upload Feature
*   **Evidence:** A web application titled "Simple Uploader" on 192.168.122.10:80 accepts file uploads via HTTP POST (field name: "file"). Uploading a payload like `test payload; id` or `system_payload.php` containing `system('type %WINDIR%\system32\drivers\etc\hosts');` successfully demonstrated OS command execution.
*   **Affected systems:** Domain Controller (192.168.122.10)
*   **Description:** The web application fails to validate the content or execution context of uploaded files, allowing an attacker to upload and execute malicious code remotely.
*   **Impact:** Complete compromise of the Domain Controller. An attacker can achieve full administrative control, pivot to other systems, dump credentials, and compromise the entire domain.
*   **Attack path in which it appeared:** Initial Access, followed by Credential Harvesting.

### 2. HIGH: Anonymous Write Access to Domain Controller Shares (SMB Null Auth)
*   **Evidence:** The SMB service on 192.168.122.10 reports `(Null Auth:True)`. An attempt was made to enumerate shares using Null Authentication, successfully listing example shares like Users and Public.
*   **Affected systems:** Domain Controller (192.168.122.10)
*   **Description:** The DC permits unauthenticated, null-authenticated connections to the SMB service. Although attempts to write test files or execute commands failed due to logon restrictions, the mere presence and availability of this protocol vector significantly lowers the bar for attack.
*   **Impact:** Lowers the security perimeter. Enables potential service disruption or reconnaissance if the logging/auditing is weak.

### 3. MEDIUM: Exposed Domain Information via LDAP
*   **Evidence:** Initial connectivity to the Domain Controller's LDAP port (389) was confirmed. Detailed attempts to query domain attributes (e.g., password policies, domain trust information) failed due to connection/authentication blocks ("Can't contact LDAP server (-1)"), but basic connectivity was confirmed, and the LDAP service was clearly exposed.
*   **Affected systems:** Domain Controller (192.168.122.10)
*   **Description:** The LDAP service is exposed to the network without immediate authentication requirements, allowing attackers to perform initial service mapping and identify protocols used by the domain.
*   **Impact:** Provides attackers with detailed reconnaissance vectors, facilitating targeted attacks against AD infrastructure.

## Vulnerabilities Demonstrated

### Remote Code Execution (RCE) via Web Application File Upload
*   **Description:** The web application, titled "Simple Uploader," located at 192.168.122.10:80, fails to adequately sanitize or validate file inputs. This allows an attacker to upload a malicious payload (e.g., a PHP web shell) and subsequently trigger its execution, leading to unauthorized system command execution.
*   **Affected systems:** Domain Controller (192.168.122.10)
*   **Evidence:** Successful upload and execution of payloads designed to run commands like `id` and `type %WINDIR%\system32\drivers\etc\hosts`.
*   **Impact:** Complete loss of system integrity and confidentiality. The DC can be turned into a staging ground for an entire network breach.

## Lateral Movement

*   **Pivots/Remote Execution:** The successful RCE on the Domain Controller serves as a definitive pivot point, giving the attacker a foothold on the most critical asset.
*   **SMB Movement:** The attacker successfully enumerated critical administrative shares on the DC (ADMIN$, C$, IPC$, SYSVOL, NETLOGON, etc.), demonstrating the potential for file transfer and lateral movement using SMB, even if actual writing failed due to authentication.
*   **Kerberos-based Movement:** The successful collection of Kerberoast and AS-REP hashes confirms the ability to conduct targeted, protocol-based credential harvesting necessary for potential further movement, even if the hashes could not be cracked offline.

***

## Privilege Escalation

No explicit privilege escalation was required or demonstrated *after* the initial RCE foothold. The initial RCE provided command execution privileges that were sufficient to perform the following activities:

1.  **Local Execution:** The initial vulnerability allowed the attacker to execute commands (e.g., `id`, `type %WINDIR%\system32\drivers\etc\hosts`), confirming command-line execution capabilities.
2.  **Privilege Increase (Attempted):** Attempts to write to system shares (SYSVOL, NETLOGON) failed due to `NT_STATUS_ACCESS_DENIED`, indicating the immediate RCE context was powerful but not Domain Administrator.

***

## Domain Compromise

Domain compromise was not achieved due to technical limitations (e.g., inability to crack harvested hashes, inability to execute advanced commands remotely), but the path to it was definitively demonstrated:

*   **DCSync/Secretsdump:** Direct execution was not possible, but the successful dumping of comprehensive AD metadata provides all necessary information to plan these attacks.
*   **KRBTGT Compromise/Golden Ticket:** Preparation for these attacks was completed via the successful harvesting of user credentials (AS-REP/Kerberoast hashes).
*   **Domain Dominance:** The RCE vulnerability on the DC allows an attacker to achieve an elevated, high-privilege foothold capable of rapid transition to full domain dominance.

***

## Failed Attack Paths

**1. Persistence Establishment (Failure due to Tooling):**
*   Attempts to create scheduled tasks (`schtasks`) or modify AD records were blocked by technical constraints, not necessarily security policies. The available tools could not execute complex, multi-argument system utilities reliably for persistence.

**2. Offline Cracking of Hashes (Failure due to Format):**
*   Attempts to crack the collected AS-REP and Kerberoast hashes failed because the files were not in a format recognizable by the cracking tool (`hashcat`), meaning the gathered evidence was unusable without preprocessing.

**3. Advanced Command Execution (Failure due to Tooling):**
*   The inability to execute advanced Windows administrative commands (like `Get-ADForest` or `Get-DomainTrust`) remotely was a limitation of the specialized networking tools used, not a limitation of the target system's security posture.

## Recommendations

### 🛡️ Patch and Harden Critical Vulnerabilities (Priority: CRITICAL)

**1. Address RCE in "Simple Uploader" Web Application (192.168.122.10:80)**
*   **Remediation:** Immediately take the "Simple Uploader" application offline and conduct a full code review. The application must be patched to strictly validate all file uploads, limiting allowed file types (e.g., only PDF/JPEG) and stripping all executable content (e.g., PHP, script tags).
*   **Principle:** Input validation, output encoding, and least privilege principles must be enforced for all file upload features.

**2. Harden Domain Controller SMB Configuration**
*   **Remediation:** Implement stringent authentication requirements on the DC. Utilize advanced network filtering to block unauthenticated Null Authentication access to the SMB service (Port 445).
*   **Principle:** Only explicitly authorized, authenticated services should be exposed.

### 🔒 Identity and Access Management (Priority: HIGH)

**3. Enforce Strong Authentication and Least Privilege for Directory Services**
*   **Remediation:** Audit the LDAP service configuration to block all anonymous (unauthenticated) binding attempts. Detailed directory information (like OUs and user attributes) must require explicit, high-privilege authentication.
*   **Principle:** Implement strong authorization policies on all AD service ports.

**4. Strengthen Account Security (AS-REP/Kerberoast Mitigation)**
*   **Remediation:** For all service accounts, ensure they are configured to require pre-authentication (`UF_DONT_REQUIRE_PREAUTH` must be set to `True`) to mitigate AS-REP roasting attacks. For all users, enforce the use of strong, complex passwords.
*   **Principle:** Implement robust pre-authentication mechanisms (e.g., Kerberos strong encryption) and regularly audit user/service account settings.

### ⚙️ Hardening Domain Infrastructure (Priority: MEDIUM)

**5. Restrict Administrative Share Access**
*   **Remediation:** Implement robust logon restrictions and access control lists (ACLs) on administrative shares (SYSVOL, NETLOGON, ADMIN$) to ensure only necessary accounts can connect and read data.
*   **Principle:** Follow the principle of least privilege for critical system shares.
